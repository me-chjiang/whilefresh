# Loop Dev Cycle

从用户需求出发，完成需求对齐、规划、实现、迭代和验收。启动方式：`启动 loop-dev-cycle：<需求描述>`。参数可选：`budget_usd=20`、`max_revisions_per_milestone=3`；未提供时使用默认值。

## 核心规则

- 规划确认、阶段交付和最终验收是用户 gate；到达 gate 后等待用户明确确认再推进。
- 将进度、决策、偏差、预算和验证结果写入 `CYCLE_STATE.md`。恢复时先读状态摘要、未完成项和本次相关文件范围，再读必要文件。
- 每次启动或恢复、以及进入新阶段前，估算主代理、子代理和外部付费调用的总费用。不可见用量按未缓存输入、预计输出及 1.5 倍余量估算，并标为“估算”。
- 默认总预算为 $20：Phase 0 $1、Phase 1 $2、Phase 2 $10、Phase 3 $4、Phase 4 $2，停止后的总结另留 $1。阶段预算不能自动挪用；用户可调整分配。启动估算已超过可用预算时，不开始该阶段并报告。
- 记录实际可见的 token 用量和费用；不可见时持续记录估算及依据。用可靠用量计算时，在下一步预计越过阶段或总预算前停止；仅有估算时，在相应工作预算达到 80% 时停止。估算阈值不是账单硬上限。
- 达到成本阈值后停止开发和验证。可用时交由 Codex Luna 或 Claude Haiku，提供精简状态并要求报告已用量、超支原因、未完成验证和剩余工作；没有廉价模型时直接输出同样的简短报告。
- 每个大里程碑的审阅和验证退回合计最多 `max_revisions_per_milestone` 轮，默认 3。达到上限后停止并报告，不开始下一轮。
- 开发中可编写必要测试；不因每个功能或模块完成就运行全量测试。阶段末做与该阶段相称的检查。每个大里程碑先审阅变更，通过后做一次全量验证；交付前确保有一次针对当前代码的全量验证。审阅或验证退回后先运行相关检查，代码稳定后再过全量关卡。
- 遵守仓库现行工程约定。此项目修改 C++ 后，保留 `scripts/build-desktop.sh`、`ctest --test-dir build/desktop --output-on-failure` 及合并前验证要求；合并仍须用户确认。
- 恢复和审阅以状态摘要及 diff 为入口；日志只读失败段或末尾。不要无目的地重读全库、完整历史或将大段输出带入上下文。
- 每个大里程碑结束时保存简短恢复摘要。若有可调用的 compact 能力则使用；否则提示用户输入 `/compact`。Codex 官方命令文档将 `/compact` 列为交互命令，skill 不应声称能直接执行。

## 阶段

### Phase 0：需求对齐（默认 $1）

将需求转成明确、可验证的规格；识别关键歧义和假设，必要时询问用户。产出 `REQUIREMENTS.md`，包括目标、分层功能、非功能需求、边界和验收标准。用户确认后进入 Phase 1。

### Phase 1：规划（默认 $2）

形成可执行方案，说明架构、关键选择、任务顺序、依赖与风险。产出 `PLAN.md`。用户确认后进入 Phase 2。

### Phase 2：执行（默认 $10）

按计划实现并更新状态。每个大里程碑保存摘要、审阅变更并做相称的验证；不要按单个功能重复跑全量验证。阶段末对照需求检查覆盖情况。

### Phase 3：迭代（每次迭代默认 $5）

结合审阅及验证结果修复问题。退回轮数受每个大里程碑的上限约束；记录修复、设计调整、验证结果及未解决问题。迭代报告完成后，等待用户确认进入 Phase 4。

### Phase 4：验收（默认 $3）

交付前完成当前代码对应的全量验证，输出成果、验证结果、限制及后续工作。等待用户验收；不通过时记录反馈并返回相关阶段，仍受预算和退回上限约束。通过后将 `CYCLE_STATE.md` 标为 `COMPLETED`，仅在需要时更新 README 或归档文档。

## 状态格式

在 `CYCLE_STATE.md` 中维护以下要点，保持简短，便于恢复：

```markdown
# Cycle State

## 当前阶段与摘要
Phase X；当前里程碑及最近完成事项。

## 未完成项
- [ ] ...

## 预算与用量
总预算、阶段预算；各阶段已用金额及依据（可见用量或估算），剩余预算。

## 退回轮数
当前里程碑：N / 上限。

## 决策与偏差
- 决策、原因；计划偏差及原因。

## 验证
- 检查项、结果、对应代码状态；尚未完成的验证。
```

## 暂停或停止

用户要求暂停/停止，预算阈值触发，或达到退回上限时：保存状态并停止后续开发与验证，输出简短摘要，列明已用量及其依据、超支原因（如有）、未完成验证和剩余工作。等待用户下一步指示。
