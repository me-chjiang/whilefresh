- 同时最多 3 个子代理并行。写代码的子代理在 git worktree 中工作。
- 本会话中 Haiku 出现过一次配置报错（缺 `base_url`），重跑后成功；如再出现，改用 Sonnet。

## 分支与审阅流程

1. main 只接收审阅通过的合并。每个功能一个分支，如 `feat/recipe-data`、`feat/fridge-view`。
2. 主会话先审查 diff，再由 Sonnet 子代理做代码审查；测试通过后，把摘要交给用户。
3. **用户确认后才合并**；不推送远端。
4. 提交信息遵循 Conventional Commits，不添加 AI 署名。

## 技术验证记录

### 2026-10-20 DeepSeek 视觉识别（美团小象购物车长截图，1100×6993）

- 接口：`https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`；图片用 `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`，只能放在 user 消息中。`response_format: json_object` 与图片同时使用可正常返回。来源：https://api-docs.deepseek.com/guides/vision
- 官方限制：超过约 1300×1300 像素总量的图片会被等比缩小；每张图最多计 1024 token；单张最长边不超过 8192 px。
- 整张发送：约 9 秒，共约 3.8k token；切成 6 片后在同一请求中发送：约 9 秒，共约 8.3k token。
- 两种方式都识别出全部 15 项勾选商品，包括赠品，生产日期（含"今天/昨天生产"）也全部正确；换购、热卖、凑单、横幅都正确排除。
- 切片版的原名转写更准确，整张版有个别错字和漏字。首版默认切片；超长截图的 token 消耗约为整张发送的 2 倍。
- **问题 1：标准食材名不稳定**：两次结果分别为"麻辣香肠/川味香肠""大拌菜/沙拉菜"。需要在提示词中给出固定词表，让模型只从词表中选择。
- **问题 2：保质期估计不稳定**：同一款香肠冷藏天数两次分别为 30 和 90，常温一次为空、一次为 30。常见食材改用本地参考表，AI 只为表外食材补充，且结果按标准名缓存。
- 接收系统分享和相机需要 Android 原生桥接（`content://` URI、冷 / 热启动），Qt 不会自动处理。
- HowToCook 的 Markdown 结构尚未抽样核实。
- Qt LGPL 分发义务需在交付前核对（非法律意见）。
- arm64-v8a APK 已能构建，尚未在真机运行。
- 桌面版使用本机另装的 OpenSSL 3.6.3，来源未核实；不影响 Android。
- AndroidManifest 中 Qt 模板遗留的 `requestLegacyExternalStorage`、FileProvider、`allowBackup` 在 T9 清理。
- 目前只有美团小象一个平台的样例，其他平台待补充。
