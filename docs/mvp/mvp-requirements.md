# 趁鲜 MVP 需求确认稿

> loop-dev-cycle Phase 0 产出，2026-10-20。以 [PRD v5](../prd-v5.md) 为基线，结合需求对齐会话中的决定整理。状态：**用户已确认（2026-10-20）**。

## 目标陈述

让单人用户在 Android 手机上轻松记下冰箱里有什么、哪些该先用，并用这些食材找到有来源的菜谱。

## 交付形态与技术约束

| 项 | 决定 |
| --- | --- |
| 平台 | Android APK，可在 Android 模拟器运行；另有离线演示模式，界面明确标识"演示" |
| 客户端 | Qt Quick/QML + C++，沿用本机 Qt 6.8.2、NDK 26.1、JDK 17、Android API 34；本轮只验收 Android，代码结构为后续跨平台保留空间 |
| 试用对象 | 少量中国大陆用户，异地独立使用 |
| 后端 | 不部署。App 直接调用 DeepSeek 多模态 API 识别截图、小票和订单文字 |
| 识别模型 | DeepSeek `deepseek-flash`（官方标注实验性，支持图片输入）；识别层做成可替换接口，备选阿里云百炼 Qwen-VL |
| API 密钥 | 试用专用限额密钥，构建时从本机钥匙串注入，不进仓库；APK 只发给认识的试用者，试用结束后作废 |
| 菜谱数据 | [HowToCook](https://github.com/Anduin2017/HowToCook) 全量，仅文本，不含图片；随 APK 内置 |
| Python | 离线工具：HowToCook 转换为内置菜谱数据、生成合成测试数据、数据校验与测试 |

## 相对 PRD v4 的修订

1. **冰箱视图**：PRD v4 写"不做常驻库存管理页"。改为轻量冰箱首页，列出已确认的物资、存放位置、新鲜度和先用标记；不追踪精确消耗量，不做统计报表。
2. **保质期与临期**：PRD v4 写"不依据购买日期宣称食材即将过期"。改为记录每个食材的保质期并显示临期状态，保质期可由 DeepSeek 估计。约束见下方"保质期与临期"一节。
3. **导入方式**：新增粘贴订单文字、拍购物小票照片。

以上修订已并入 [PRD v5](../prd-v5.md)。

## MVP 功能

### 1. 冰箱（首页）

- 按冷藏 / 冷冻 / 常温分区。
- 每行显示品类色点、名称、数量原值（如"500g""10枚"）、新鲜度标记、先用标记。
- 左滑"用掉 / 家里没有"，右滑"先用"，长按进入多选。
- 可编辑名称、数量、存放位置和各类日期。

### 2. 清冰箱做饭（最醒目入口）

- 底栏中间的大圆按钮，是全 App 视觉权重最高的操作。
- 打开后默认勾选临期和标记先用的食材，用户可增减。
- 菜谱按"用到所选食材最多、缺料最少"排序，常备调料和食材规则参与判断。

### 3. 入库（次要入口）

- 入口在冰箱页右上角"＋ 入库"；冰箱为空时放大显示。
- 导入方式：
  - 相册选图，可多选，合并后去重；
  - 接收 Android 系统分享的图片；
  - 粘贴订单文字；
  - 拍购物小票；
  - 手动添加单项（不调用 AI）。
- 识别结果分三类：
  - **食材**：进入冰箱，存放位置按第 4 节的优先级给出建议，用户可改；
  - **调料**：用于更新常备调料；
  - **无关内容**：日用品、配送费、优惠、推荐商品等，默认折叠为"已忽略 N 项"，可找回。
- 用户确认后才写入冰箱。疑似重复导入时提示。
- 上传前提示内容将发送到 DeepSeek，截图可能含收货地址等个人信息。

### 4. 保质期与临期

- **不把导入时间当作生产日期。** 各日期分开记录：
  - 购买日期：订单或小票上可见的时间，或用户填写；
  - 入库日期：导入时自动记录；
  - 生产日期、包装到期日：仅在截图、小票上可见或用户填写时才有。
- 截图中的相对日期（如"今天生产""昨天生产"）以**截图当天**为基准：优先取图片文件的日期信息，取不到时请用户确认。
- **保质期信息来源优先级**（高者覆盖低者）：
  1. **识别结果**：截图、小票或包装上可见的到期日、生产日期、标注保质期；
  2. **本地记忆**：用户以前对同一标准食材（及存放方式）确认过的保质天数或存放位置；
  3. **参考表**：App 内置的常见食材 × 冷藏 / 冷冻 / 常温保质天数；
  4. **AI 判断**：仅在前三者都没有时，使用 DeepSeek 的估计。
- 存放位置建议同样按"本地记忆 > 参考表 > AI 判断"确定。
- 到期日的起算日：生产日期（可见时）> 购买日期 > 入库日期。只有包装上直接标注到期日时才不需要起算。
- 每个食材记录到期日取自哪一级来源，界面上标出"包装标注 / 你的设置 / 参考表 / AI 估计"；除包装标注外，均标为"估计"。
- 用户可随时调整单个食材的日期、保质天数和存放位置。调整后询问"以后同类食材都按这个吗？"，用户确认后才记为本地记忆规则。规则可在"我的"中查看、修改和删除。
- 识别时一次性返回冷藏、冷冻、常温三种保质天数，供参考表和本地记忆都没有覆盖时使用；用户修改存放位置时直接换算，不再调用 AI。AI 结果按标准食材名缓存，避免同一食材前后不一致。
- 新鲜度在每次打开 App 和跨日时按当天日期重算，分为：新鲜 / 临期 / 超出估计期限。
- 不使用"可安全食用""已变质"等结论性表述；超出估计期限时提示"请查看后决定"。

### 5. 菜谱

- 数据来自 HowToCook 全量，保留原用料、步骤和来源链接；不使用 AI 生成或改写菜谱。
- 构建前离线用 AI 把用料统一为标准食材名，结果经抽查后固定；App 内只做本地规则匹配。
- 识别时，提示词中附上固定的标准食材词表，DeepSeek 只能从词表中选择标准名（词表外的标为"未归类"，由用户确认），使冰箱物资与菜谱用料能对上。实测表明不给词表时，同一商品两次的标准名不同。
- 列表显示来源和"有 N · 缺 M"；详情标出每项用料有 / 缺。
- 用时只在来源提供时显示；无匹配时允许改选食材。

### 6. 待买

- 内容来自做菜缺的料，以及用户确认用完的常备品。
- 按品类分组，可删除、复制文字、系统分享。
- 不显示价格、库存或"一键买齐"。

### 7. 我的

- **常备调料 / 常用食材规则**：
  - 预置默认清单（如盐、油、生抽、米、葱姜蒜），清单内的物品默认"家里有"，不算缺料；用户可增删；
  - 可把某些食材设为"默认存量多"，用掉一次不会从冰箱移除；
  - 系统建议的任何状态变更（如导入时发现买了生抽、推断某常备品用完）都必须由用户确认，不静默修改。
- **保质期与存放规则**：查看、修改、删除用户确认过的本地记忆规则。
- 演示模式开关。
- 删除全部数据，或删除某次导入的截图及由其生成的记录。
- 菜谱来源与许可说明。

### 8. 离线演示模式

内置合成截图和对应识别结果，断网时也可走通完整路径；界面始终标识"演示"，不把模拟识别当作真实识别结果。

## 界面

### 底栏

冰箱 | 菜谱 | 〔清冰箱〕 | 待买 | 我的

"清冰箱"是中间的大圆按钮，视觉上比"＋ 入库"更醒目。

### 视觉风格

- 略带拟物，有生活感、亲切感和活力，不沉闷。
- 暖白纸张底色，带轻微质感：
  - 冰箱分区像冰箱隔层，物资行像冰箱贴或标签；
  - 待买像便签纸，菜谱详情像菜谱卡片；
  - 阴影柔和。
- 品类色：蔬菜绿、肉类番茄红、海鲜蓝、蛋奶黄、主食麦色；只用于小色点和标签，不铺大面积色块。
- **不用 emoji 当图标**，使用许可清楚的线条图标集或自绘 SVG。
- 控件视觉紧凑，常用操作放在滑动和长按中；点击区域保持约 48dp。空间优先留给冰箱物资和菜谱。
- 先用 HTML 做两版视觉稿供确认，确认后再写 QML。

## 首个真实样例的发现

样例位于 `private/bill/`（不进 Git），是一张美团小象超市购物车长截图。对需求的影响：

- **购物车与订单要区分处理**：只有勾选的商品算数；换购推荐、热卖推荐、凑单提示、优惠横幅属于无关内容。
- **赠品**（¥0）也是买到的食材，需要计入。
- **截图中可见生产日期**，包括相对日期，按上文规则以截图当天为基准。
- **超长截图**（约 1100×6993 像素）：DeepSeek 公告称每张图最多计 384 token，整张直接发送可能看不清。需要在客户端按重叠窗口切片后分别识别，再合并去重。
- **规格写法多样**（如"200g""10枚530g""125g(18mm)""单果30g起"），商品名带营销括号，需要归一为标准食材名和数量。
- **实测（2026-10-20）**：DeepSeek 对该样例整张或切片识别都找出了全部 15 项勾选商品（含赠品）和可见生产日期，并正确排除推荐内容；切片转写更准确。但不给词表时标准名前后不一致，AI 保质期估计前后差异大，因此采用固定词表和上述保质期优先级。详见 [cycle-state](cycle-state.md)。

## 分层范围

- **MVP**：上述 1–8 项。
- **增强**：临期提醒通知、上传前自动裁掉地址栏、附近门店（高德 POI）、淘宝订单 API、识别服务切换。
- **未来**：多人 / 家庭协作、iOS 等其他平台。

## 非功能需求

- Android 9（API 28）及以上；arm64 真机与 x86_64 模拟器。
- 中国大陆网络直连可用。
- 识别有超时，失败可重试，错误提示可理解。
- 时间来源可注入，便于测试新鲜度随时间变化。
- 密钥不出现在仓库中。
- 适合做饭时单手、短时查看。

## 明确不做

- PRD v4"明确不做"中仍适用的各项：家庭协作与权限、完整库存统计和报表、AI 编造菜谱、自动监控其他 App 截图、自动读取购物账号或代下单等。
- 不部署后端，不做账号与云同步。
- 不交付 iOS 或桌面版本。
- 不显示价格、门店库存或"可买齐"承诺。
- 不给出食品安全结论。

## 测试数据

- **合成截图**：用 HTML 仿各平台订单页和购物车页（不使用平台 logo），填入虚构商品，并混入日用品、配送费、优惠、推荐商品；用 Playwright 渲染成手机尺寸 PNG，每张附标准答案 JSON。
- **合成小票**：同样方法生成，另加倾斜、模糊、阴影等变体，模拟拍照效果。
- **粘贴文字样例**：覆盖各平台订单文字格式。
- **录制回放**：DeepSeek 的真实返回录制后供离线测试回放；真实调用须经用户同意，小批量手动运行。
- **本机数据状态**：预置空冰箱、满冰箱、多数临期、无匹配菜谱等状态。
- **真实样例**：存放于 `private/bill/`，由用户持续补充，用于识别验证和验收。

## 验收标准

> 2026-10-21 用户调整设备验收口径：以后以本机运行结果判断 Android 可运行，不以连接 arm64 真机实测作为前置；验证记录仍应如实区分本机运行、APK 构建与真机实测。

1. 在本机走通，并通过 Android APK 构建：入库 → 分类纠错确认 → 冰箱中可见并显示新鲜度 → 清冰箱做饭 → 菜谱详情含来源 → 缺料加入待买并复制 / 分享 → 标记用掉。
2. 断网时，演示模式可走通同一路径。
3. 注入时间推进 N 天后，新鲜度状态按规则变化；保质期来源按"识别结果 > 本地记忆 > 参考表 > AI 判断"取值，界面标出来源；用户调整并确认后形成的规则在下次导入同类食材时生效。
4. 在合成样本上记录食材 / 调料 / 无关内容的分类结果与标准答案的差异。
5. `private/bill/` 中各平台真实样例完成识别，记录每张的修正项数和耗时；首版只收集基线，不设达标阈值。
6. 空冰箱、识别失败、重复导入、无匹配菜谱、未知用时、超出估计期限等状态，都有可继续的操作。
7. 常备规则的任何系统建议变更都需要用户确认。
8. 仓库中检索不到密钥。
