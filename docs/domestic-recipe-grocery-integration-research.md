# 国内菜谱与买菜平台接入调研报告

> AI 辅助整理，2026-10-20。调研完成于 [PRD v4](archive/prd-v4.md) 阶段，其结论支撑 [PRD v5](prd-v5.md) 的数据来源决定。核查依据包括公开网页、官方条款、开放平台文档及开源项目。网页抓取已恢复；登录后客户端功能尚未实测。以下区分“公开接口未提供证据”和“客户端功能未实测”，不以搜索不到证明接口绝对不存在。

## 执行结论

1. **菜谱内容**：首版有可用的开放数据路径。[HowToCook](https://github.com/Anduin2017/HowToCook) 提供中文菜谱，仓库级许可为 [Unlicense](https://github.com/Anduin2017/HowToCook/blob/master/LICENSE)。下厨房、豆果的网页内容虽可获取，但现有条款不允许据此直接做商业全文/图片抓取和再展示；美食杰的网页抓取受阻，小红书公开 API 目录没有菜谱读取类别。
2. **消费者已购数据**：[淘宝买家订单 API](https://open.taobao.com/api.htm?docId=45&docType=2) 文档明确存在，描述为经用户授权查询当前买家近三个月交易；应用能否获得该接口权限、是否覆盖淘宝买菜/淘鲜达订单仍须验证。其他已查平台未发现同类公开接口。盒马、叮咚、淘宝、京东、拼多多的官方政策明确提供个人信息下载入口，但下载包是否含逐商品订单，须由账号持有人实测。首版暂不依赖购物平台直连，采用用户主动提交、可修正的订单截图或清单。
3. **待买清单**：未找到这八类买菜平台公开、可授权使用的购物车清单导出或批量导入接口。拼多多政策确认平台层有单商品/服务分享组件，但不能推出多多买菜购物车清单分享。首版输出可复制缺料清单，由用户在平台内完成选品。
4. **附近补货**：[高德地点搜索 API](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) 能找附近门店；第三方盒马 MCP 能查询门店及已知 ID 的商品，但拿不到匿名门店商品列表或库存。这两者不足以证明某店能买齐缺料，产品只能标“附近门店”，不能标“有货”。

## 判定口径与调查范围

“有”指有官方明示的功能或本轮实际取得公开返回；“没有公开可接入方案”指已检查的官方开放平台目录和公开政策没有面向第三方的消费者读取或清单写入接口，**不等于断言平台内部不存在私有合作能力**；“未实测”专指需要账号、地区或客户端操作才能确认的功能。生产可接入还须同时满足接口权限、内容许可、稳定性和字段需求，网页 HTTP 200 不算通过。

本轮用未登录网页请求核查官方站点、用户政策、开放平台及 GitHub 项目；淘宝 API 文档和叮咚政策的动态页面通过公开页面正文提取服务辅助读取，引用仍指向官方原文。未申请开发者权限、未登录购物 App、未取得账号数据或进行下单。研究日期和动态数量均为 2026-10-20；客户端界面与授权范围可能随地区、版本和账号变化。

## 调研口径

只看国内服务，并区分两个方向：

- 平台到产品：从购物平台取得消费者已购商品、订单明细或待买购物车清单，用于推测待消耗食材和减少重复录入。
- 产品到平台：把缺料或待买清单送给买菜平台，供用户下单。

“用户可见订单”“商家订单 API”“消费者本人订单 API”是不同能力；“分享文字清单”“分享单个商品”“批量导入购物车”也不能互相推断。API、网页抓取、MCP 和 skill 都需要分别核实数据权限与内容授权。

## 买菜平台

“个人信息下载”是用户手动取回个人数据的路径，不等于开放 API，也不保证下载包含逐项订单或购物车。下表把两者分开。

| 平台 | 官方已确认的消费者功能 | 已查公开 API 的结论 | 本轮未确认的关键环节 |
| --- | --- | --- | --- |
| 盒马 | [政策](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_alibaba_hema/suit_bu1_alibaba_hema202203300948_54070.html)确认“我的订单”、商品/服务分享、购物车和“我的-设置-其他设置-个人信息下载” | 未找到公开的本人订单或购物车接口；第三方盒马 MCP 非官方 | 下载包字段、分享外链、完整购物车导出/导入 |
| 叮咚买菜 | [政策](http://maicai.api.ddxq.mobi/info/single?alias=privacy_policy)确认商品分享、订单管理和“我的-设置-个人信息收集清单-个人信息下载”；下载需登录及短信验证 | [开放平台](https://open.ddxq.mobi/docs)采用开发者应用及接口申请，公开场景是供应商、ERP、采购/销售单据；未见消费者订单/购物车接口 | 下载包字段、分享外链、购物车导出/导入 |
| 小象超市 / 美团闪购 | [小象政策](https://rules-center.meituan.com/rules-detail/31)确认“我的-全部订单”可查；[美团通用政策](https://rules-center.meituan.com/rules-detail/2)有“我的-设置-隐私设置-个人信息下载”入口 | [零售开放平台](https://developer-lingshou.waimai.meituan.com/docCenter/2)面向商家商品、门店、仓库及订单系统；未见消费者本人订单接口 | 通用下载是否包含小象订单、商品外链、购物车导出/导入 |
| 淘宝买菜 / 淘鲜达 | [淘宝政策](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_taobao/suit_bu1_taobao201703241622_61002.html)确认交易订单、购物车及个人信息下载，也提及“特定购物车分享链接的推荐” | **有**[买家订单 API](https://open.taobao.com/api.htm?docId=45&docType=2)，经用户授权可查近三个月交易；公开文档未展示可申请的权限组或购物车清单 API | 应用能否获批、是否覆盖买菜订单、分享链接实际内容、购物车导出/导入 |
| 京东到家 / 京东买菜 | [京东政策](https://in.m.jd.com/help/app/private_policy.html)确认“我的订单”和“我的-账户设置-隐私设置-个人信息下载” | [京东 API 列表](https://jos.jd.com/apilist)面向京东商家、ISV、个人开发者及合作伙伴的业务系统；未见消费者本人订单/购物车接口。“个人开发者”不等于买家数据权限 | 下载包是否含买菜逐项订单、商品分享和清单导入/导出 |
| 朴朴 | 官网可访问；本轮[隐私政策入口](https://c.pupuapi.com/static/agreement/UserPrivacyPolicy.html)只得到动态页面外壳 | 未找到公开的消费者订单/购物车 API 文档 | 订单或清单下载、商品分享、批量加购均需客户端核查 |
| 永辉生活 | [隐私政策入口](http://activity.yonghuivip.com/h5/yh-activity/user_privacy/index.html)正文未能通过本轮网页抓取核实 | [永辉开放平台](https://open.yonghui.cn/static/page1.html)明确基于供应链，接口按供应商范围取订货数据，不是消费者本人订单 | 订单或清单下载、商品分享、批量加购均需客户端核查 |
| 多多买菜 | [拼多多政策](https://mobile.yangkeduo.com/private_policy.html)确认“我的订单”、“个人中心-设置-账号与安全-个人信息下载”和平台层商品/服务分享组件 | [拼多多订单 API](https://open.pinduoduo.com/application/document/api?id=pdd.order.list.get)有公开页面，但本轮没有获得可证明买家本人授权查询的权限正文；未见消费者购物车接口 | 下载包是否含买菜订单、单品分享在外部的行为、购物车导出/导入 |

淘宝的 `taobao.trades.bought.get` 文档明确写明“当前会话用户作为买家达成的交易记录”、用户授权和近三个月限制，响应字段含交易及子订单。它是本轮发现的**消费者订单 API 定义**；但文档的“可获得/可申请此 API 权限组的应用类型”显示“没有数据”，所以不能称本项目已能调用。淘鲜达/淘宝买菜订单覆盖也没有得到官方文档证实。与之相对，[卖家订单 API](https://open.taobao.com/api.htm?docId=46&docType=2)明确面向卖家；不能把商家订单查询当作家庭已购数据。

对其余平台，本轮结论是**已查公开入口没有可直接用于普通消费者订单或购物车的接口**，而非断言内部不存在任何接口。购物车整单分享/导出、第三方批量导入购物车没有获得可操作的官方说明；淘宝政策提及购物车分享链接，也未说明可否导出完整缺料清单。京东、拼多多、盒马、叮咚、淘宝的个人信息下载入口是真实的备选导入路径，但必须先由账号持有人查看下载文件包含哪些字段、格式与耗时。

本环境没有已安装的菜谱或买菜专用 web fetch 工具；命令行网页请求可以抓取静态 HTML 和公开 JSON，动态页面有时需要公开页面正文提取服务，登录、人机验证和平台授权不会因此消失。以下项目均不是所列买菜平台官方发布或授权的消费者接入服务：

| 项目 | 实际能力 | 与本产品的差距 |
| --- | --- | --- |
| [盒马商品查询 MCP](https://github.com/TomEageer/hema-snack-mcp) | 作者说明可匿名按已知商品 ID 查标题/常规价/图，按城市区县查门店、按门店 ID 查分类或坐标；[公开门店 JSON](https://hema-infra-center.oss-cn-zhangjiakou.aliyuncs.com/lnc/store.json)本轮可访问 | 作者明确说明匿名分类商品列表为空，会员价、库存、加购、下单需登录；商品查询不能回答“某店有缺料吗”。它逆向微信小程序，只限学习自用，未获官方接入许可 |

| [淘宝客商品 MCP](https://github.com/liuliang520530/taoke-mcp) | 面向联盟推广商品搜索和链接转换 | 联盟商品不是附近买菜门店实时商品；不提供个人已购、购物车导出或批量加购 |

代码的 MIT 等许可证仅管该项目代码，**不授予盒马、淘宝等平台数据访问权**。本轮没有找到上述买菜平台官方发布、明确面向普通消费者订单/清单的 MCP 或 skill；这是检索结论，不等于证明整个生态中绝无同名工具。

## 附近补货的可行性

要准确回答“附近哪家店能补齐这道菜缺的食材”，至少需要用户位置、门店位置、按门店可售的商品目录、商品与食材名称匹配、实时库存/配送范围。当前可核实的能力只覆盖其中一部分：

| 所需数据 | 可用路径 | 本轮判断 |
| --- | --- | --- |
| 附近超市/买菜门店位置 | [高德地点搜索 2.0](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)有关键字及周边 POI API；需注册开发者和 Web 服务 key | **可实现门店发现**，能显示名称、位置、距离；POI 不包含该店商品库存 |
| 盒马门店和商品基础信息 | 第三方盒马 MCP 可查门店、分类及已知 ID 的商品；盒马公开门店 JSON 含城市、区县、地址 | **只能辅助定位和识别商品**；匿名拿不到门店商品列表与库存，且接入授权未获确认 |
| 各平台的门店级商品目录、价格及有货状态 | 已查公开消费者 API 和非官方 MCP 均未提供可靠的跨平台数据 | **当前没有可用于“该店有货”结论的已核实接入方案**；需要平台商务授权或合作门店数据，并检验更新延迟与覆盖区域 |
| 一键把缺料加进购物车 | 已查公开接口没有可获准使用的批量加购方案 | **首版不可依赖**；可提供分品类文字清单，跳到相应平台后由用户搜索和确认 |

原型可以展示“附近可选门店”和缺料清单，但不得把距离近推断为食材齐全或有货，也不得显示未经核实的价格/库存。若未来取得门店级商品接口，应先在固定城市、少数门店实测品名匹配、缺货变化与下单后结果，再考虑“可一次买齐”排序。

## 首版方案与验证优先级

优先验证不依赖平台直连的闭环：用户主动分享订单截图，确认少量值得优先消耗的食材，查看带来源的菜谱，并能快速反馈“已用掉”或“不合适”。缺料清单先按品类整理为可复制文字，支持分享到微信；平台内的搜索和下单由用户完成。已购记录不等于家庭当前库存，截图识别结果必须允许修正。这是产品方案，不是已验证的用户行为结论。
