01 / PRODUCT

项目是什么

重点不是精确盘点冰箱，而是降低记录食材的成本，提醒「先用什么」，再帮助决定「做什么」。

目标用户

一个人买菜，也负责做饭

购物记录能说明买过，却不能证明现在还在冰箱；因此产品把 AI 识别当作低成本录入草稿，仍允许逐项纠错、手动标记用掉或家里没有。

依据docs/prd-v5.md:18–28 · :40–45
产品边界

估计有来源，菜谱有出处

保质期估计不等于食品安全结论；用户确认过的规则优先于通用参考。菜谱从有来源的离线数据导入，AI 只识别购物材料，不生成或改写菜谱。

依据docs/prd-v5.md:30–38 · :61–75

交付边界：首版是单人 Android 客户端，无账号、无后端，数据存在本机 SQLite；桌面版用于开发和自动化测试，家庭协作、iOS、自动下单及门店库存不属于当前实现。docs/prd-v5.md:59–59 · :86–93

05 / UNDER THE HOOD

值得读的五组算法

下面写的是实际代码路径与边界，而非「AI 自动解决一切」。

A / INPUT 从图片 / 文字到可信草稿

导入端先检查文件路径、数量和体积；超长图像本机缩放、切片，再按批次请求 DeepSeek。识别响应经过 JSON 解析、字段范围限制、标准名映射；截断响应只保留完整商品，原始识别结果需要用户确认才能入库。

  • 相对日期以截图拍摄日解释，不能把「今天生产」理解为导入当天。
  • 相同图片按 SHA-256 判重；近 3 天导入的商品按「标准名 + 数量」多重集合比较，至少两项且重合达到 80% 才提示疑似重复。
  • 识别器接口同一套，可切换真实 API、录制回放和演示预置。
app/src/platform/import-files.h:22–25 · app/src/recognition/image-preprocessor.cpp:100–190 · app/src/recognition/response-parser.cpp:91–170, 315–395 · app/src/core/import-duplicates.cpp:48–80

B / EXPIRY 保质期是「依据链」，不是一个魔法数字

人工修改与包装可见信息优先，其后是用户确认过的本地规则、内置参考表、已缓存 AI 估计、新 AI 估计；没有可信期限则显示未知。日期保留「生产 / 购买 / 入库 / 包装到期」的区别，起算日依次取生产日、购买日、入库日，并在界面标明估计来源。

期限来源：人工 / 包装 → 本地规则 → 参考表 → AI 缓存 / 新估计
起算日期：生产日 → 购买日 → 入库日（依次回退）
app/src/core/shelf-life.cpp:225–315 · app/src/core/fridge-item.cpp:64–87 · app/src/ui/import-service.cpp:167–224

C / TIME 新鲜度按天重算

过了估计到期日（含到期当天）标「超出估计」；剩余天数不超过 max(1 天, 总保质天数 × 25%) 为临期；无日期为未知。它是帮助决定先用什么的提示，不是食用安全鉴定。

remaining = expiryDate − today
remaining ≤ 0 → 超出估计；remaining ≤ max(1, totalDays × 0.25) → 临期
app/src/core/freshness.h:17–21 · app/src/core/freshness.cpp:39–52 · docs/prd-v5.md:69–70

D / MATCH 食材集合匹配菜谱需求组

一道菜的用料是「组间 AND、组内 OR」：例如某组可由 A 或 B 满足，子食材也可满足上位名称需求；库存和默认常备品都参与判断。清冰箱优先使用更多选中食材，再比较缺料；普通菜谱浏览优先缺料更少，不使用 AI 临时生成菜谱。

app/src/core/catalog.cpp:126–142 · app/src/core/recipe.cpp:129–194, 206–230 · app/src/ui/kitchen-service.cpp:241–305

E / CONSISTENCY 确认之后才改动持久数据

导入记录、食材、AI 天数缓存和待确认建议在数据库事务中写入；清理导入图片通过持久化队列处理，避免数据已提交却遗留无引用文件。常备品状态与保质期规则不因一次识别而静默覆盖，须经过用户操作。

app/src/ui/import-service.cpp:313–400 · app/src/data/store.cpp:446–466 · app/src/ui/kitchen-service.cpp:148–174, 189–239

07 / WHAT WORKS

值得保留的设计

这些是从实现可直接看到的优点，而不只是架构图上的口号。

规则能单测，不绑 UI

日期、保质期和匹配逻辑沉在 core，有 QtCore 依赖检查；UI 服务做编排，QML 不承担业务规则和 SQL。

真实、回放、演示共享入口

识别器实现同一个异步接口，允许离线回归与断网演示；演示数据库与真实数据库隔离，避免测试数据混入个人冰箱。

有来源、可纠错、可复现

保质期带来源标签，菜谱保留原文与来源；离线词表/菜谱/参考表由工具生成和校验，而不是运行时临时让 AI 编造。
