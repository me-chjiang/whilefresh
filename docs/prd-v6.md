# 趁鲜（WhileFresh）PRD v6

> AI 辅助整理，2026-10-29。在 [PRD v5](archive/prd-v5.md) 和试用版 0.1.0 的基础上，按第二轮需求会话修订。本轮先把功能做对，界面能用即可，视觉之后再调。工程计划见 [第二轮计划](mvp/round-2-plan.md)。

## 相对 v5 的主要变化

| 项 | v5 | v6 |
| --- | --- | --- |
| 导航 | 冰箱 / 菜谱 / 清冰箱 / 待买 / 我的，冰箱为首页 | 计划 / 冰箱 / ＋ / 下厨 / 我的，计划为首页 |
| 菜谱来源 | 内置 HowToCook 全量，AI 不生成或改写 | 移除 HowToCook；菜谱取自下厨房，由 AI 按库存和偏好找平替、调整用料与步骤 |
| 推荐 | 单道菜按"用到所选最多、缺料最少"排序 | 云端给出 2–4 个方案组合，每个方案必须用上全部勾选的食材 |
| 用量 | 不追踪消耗量，"用掉"只改状态 | 记录数值和单位；"做完了"按菜谱用量扣减 |
| 调料 | 只更新常备规则，不入库 | 作为"常备调料"入库，保质期由用户录入，参与临期提醒 |
| 识别 | 词表外一律"未归类" | 按上下位取最细词条；词表外的名称再用 DeepSeek 归类，用户确认后记住 |
| 删除导入 | 删除该次导入的全部食材 | 只删除仍在冰箱里的食材和截图；做成菜或扔掉的保留 |
| 重复导入 | 跳过后不留记录 | 跳过的导入也记录 |
| 中断 | 导入和推荐只保存在内存 | 导入批次和下厨会话落库，可从断点继续 |
| 提醒 | 不做 | 9:00 临期和导入提醒，20:00 核对提醒；首页弹窗每天最多一次 |
| 密钥 | 构建时注入试用密钥 | 用户在"服务"页填写 DeepSeek 和 Lexmount 密钥；演示模式使用内置密钥 |
| 偏好 | 只有保质期和存放规则的本地记忆 | 新增口味和饮食习惯记忆，整理后附在下厨相关请求的 system prompt 末尾 |

## 产品方向与原则

方向不变：帮助单人用户记住冰箱里有什么，并把快到期的食材用掉。v5 的原则继续有效，以下两条修订：

- **菜谱**：原文来自下厨房并保留原页链接；AI 只做两件事：按家里现有食材找平替、按偏好增删用料和步骤。调整内容在界面上单独列出，不混进原文。
- **库存**：开始追踪用量，因为"做完了"要扣减。但不追求精确：单位无法换算时，整件标为用完。

## 用户路径

1. **入库**：点底栏中间的"＋"，选择拍照、从相册中选择或文字导入；也可以从购物 App 系统分享过来。识别后在核对页确认，食材按冷藏 / 冷冻 / 常温 / 常备调料 / 常备食材入库。
2. **看计划**：打开 App 先到计划页，看到要处理的临期和过期食材、今天要做的菜、待买和小事（调料待录保质期、晚上核对冰箱）。
3. **下厨**：勾选要用掉的食材（默认选上临期和先用的），选一个方案组合，可以换掉其中的菜；看下厨房菜谱和平替；加入计划。
4. **做完了**：在计划页点"做完了"，预览并确认扣减，冰箱随之更新。
5. **核对**：晚上 20:00 的提醒让用户把吃掉或扔掉的划掉，保持记录和冰箱一致。

## 页面

| 页面 | 内容与动作 |
| --- | --- |
| 计划（首页） | 未完成导入的继续条；要处理（忽略 / 下厨 / 改保质期 / 扔掉；过期只有改保质期和扔掉）；今天做（菜谱、做完了）；待买；小事。全部处理完时给出"去下厨"入口；新用户冰箱为空时引导导入 |
| 冰箱 | 冷藏 / 冷冻 / 常温 / 常备调料 / 常备食材分组；组内过期在前，再按剩余天数从少到多，未知在后；左滑用掉 / 扔掉，右滑先用 |
| ＋（入库） | 只有三个入口：拍照、从相册中选择、文字导入。核对页按存放位置分组，标出"AI 归类"和"待录保质期" |
| 下厨 | 勾选食材 → 方案组合 → 方案详情（换一道）→ 下厨房菜谱（平替、有 / 缺、缺料加入待买）→ 加入计划；页面底部"随便看看"按全部库存推荐单道菜 |
| 我的 | 常备调料、常备食材、偏好记忆、导入历史（删除单次、删除历史）、服务（密钥）、演示模式、提醒、关于与致谢 |

界面文案只写标签和数值，不加解释性副标题；时间统一写"剩余x天""过期x天"；只显示例外情况，如"缺 酸奶"。

## 识别规则

- 尊重原始输入，取能对上的最细词条：原文是"黑猪梅花肉切片"就记为梅花肉，而不是猪肉；词表里没有更细的条目时才用上位词。`raw_name` 保留原文。
- 识别提示词附带分层词表（如"猪肉 > 五花肉、梅花肉、里脊"）。
- 词表外的名称：先在本地按包含关系匹配，仍不命中时批量请求 DeepSeek 归类。结果在核对页标为"AI 归类"，用户确认后记住，下次同名直接命中。
- 调料不再忽略：入库为常备调料，保质期未知时标"待录保质期"。
- 疑似重复（同一张图，或 3 天内与某次导入重合 ≥ 80%）照常提示；用户跳过时也留一条导入记录，标为"已跳过"。

## 下厨与扣减

- 方案由 DeepSeek 生成，输入包括勾选的食材、其他库存、常备品和偏好摘要。App 在本地校验每个方案是否用上了全部勾选的食材；不合格的方案丢弃，全部不合格时带着缺口重试一次。仍覆盖不到的食材在方案卡上列出（如"蓝莓直接吃"），不会悄悄漏掉。
- 断网、没有密钥或服务失败时显示错误并引导去"服务"页；不提供本地回退。
- 菜谱经下厨房菜谱源接口获取（输入密钥和关键词，返回 YAML）；子模块由外部实现，本项目只对接接口。
- 扣减在一个事务里完成，同一次下厨会话只能提交一次。

## 保质期与临期

沿用 v5 的日期分开记录和来源优先级（识别结果 > 本地记忆 > 参考表 > AI 判断）。新鲜度仍分新鲜 / 临期 / 过期。临期的"忽略"只在当天不再提醒。

## 提醒

- 9:00：临期和过期提醒；导入提醒。
- 20:00：核对冰箱提醒。
- 首页的临期弹窗每天最多一次（9:00 之后第一次打开时），其余时间这些事项都在计划页。
- Android 端由系统定时调度，不需要 App 在后台常驻；首次使用时申请通知权限。

## 数据与接入边界

- **识别和 AI 服务**：DeepSeek，App 直连，无后端。用户密钥加密保存在本机；演示模式使用构建时注入的内置密钥，须设额度上限。
- **菜谱**：下厨房，经子模块 `recipe-sources-xiachufang-api` 获取，必要时由 Lexmount 抓取。下厨房条款只允许有条件的非商业转载（见[接入调研](domestic-recipe-grocery-integration-research.md)），本轮仅限试用，不缓存或打包菜谱正文，并保留原页链接与来源标注。
- **演示模式**：内置密钥加独立的预置 demo.db，与真实数据隔离。
- **无障碍气泡**：在美团、淘宝、京东、盒马里截图时弹出导入气泡。本轮只做可行性验证（AccessibilityService 取前台应用、MediaStore 检测截图），并评估应用商店政策风险，不承诺上线。

## 明确不做

- 多人协作、账号与云同步、iOS。
- 本地菜谱库和离线推荐。
- 精确营养、浪费金额统计。
- 价格、门店库存或代下单。
