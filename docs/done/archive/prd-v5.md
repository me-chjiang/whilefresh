# 趁鲜（WhileFresh）PRD v5

> AI 辅助整理，2026-10-20。在 [PRD v4](prd-v4.md) 基础上，按 MVP 需求对齐会话的决定修订：增加轻量冰箱视图、保质期与临期、粘贴订单文字和拍小票导入，并确定 MVP 的交付形态。MVP 的详细范围与验收标准见 [MVP 需求确认稿](../round-1/mvp-requirements.md)。用户行为、内容授权和识别效果仍需验证。

## 相对 v4 的主要变化

| 项 | v4 | v5 |
| --- | --- | --- |
| 冰箱 | 不做常驻库存管理页 | 冰箱为首页，轻量列出已确认物资、存放位置、新鲜度和先用标记；不追踪精确消耗量 |
| 保质期 | 不依据购买日期宣称即将过期 | 记录保质期并显示临期；来源按"识别结果 > 本地记忆 > 参考表 > AI 判断"取值，非包装标注一律标"估计" |
| 入口 | 导入截图为主 | 两个入口：清冰箱做饭（最醒目）与入库（次要） |
| 导入方式 | 相册、系统分享 | 增加粘贴订单文字、拍购物小票、手动添加 |
| 页面 | 今天 / 菜谱 / 待买 | 冰箱 / 菜谱 / 清冰箱 / 待买 / 我的 |
| 交付形态 | 未确定技术栈 | Android APK（Qt），无后端，App 直连 DeepSeek 识别 |

## 产品方向

面向家庭做饭场景，帮助做饭者记住冰箱里有什么、哪些该趁新鲜先用，并用这些食材更快决定做什么。**首版是单人 Android 客户端**；多人协作和其他平台是后续方向。

## 需求

家中有人买菜后，食材容易被放进冰箱遗忘，直到过期。做饭者需要两件事：买菜回来时低成本地记下买了什么；清理冰箱时知道哪些该先用、能做什么菜。首版聚焦**能取得购物记录、也负责做饭决策的单人用户**。

## 主要矛盾

产品需要知道冰箱里有什么、还能放多久，才能给出有用的建议；但逐项录入和维护会额外占用用户注意力。录入越麻烦，信息越容易过时，建议也越不可靠。

购物记录只能证明"买过"，不能证明食材仍在冰箱里；多数截图也看不到生产日期和保质期。产品需要用 AI 识别降低录入成本，用可见信息、用户习惯和参考数据给出**有依据的估计**，并让用户随时纠正，而不是把推测包装成精确库存或食品安全结论。

## 产品原则

- 以用掉食材和完成做饭为中心，冰箱视图服务于"该先用什么"，不以维护库存为目的。
- 入库要轻：一次截图、粘贴或拍照即可，用户只需确认和纠错。
- 能看到的信息优先：截图上可见的日期优先于任何估计；用户确认过的习惯优先于通用参考。
- 每个保质期都能说出依据；估计值明确标为"估计"，不说"可安全食用"或"已变质"。
- 系统不静默修改用户的数据和规则：常备品状态、保质期规则的变化都需用户确认。
- 菜谱须有可追溯来源，AI 不生成或改写菜谱。
- 做饭决策先于补货，待买清单是完成这顿饭的辅助结果。

## 首版用户路径

1. **买菜回来，入库**：在冰箱页点"＋ 入库"，选择相册截图（可多张）、从购物 App 系统分享、粘贴订单文字、拍购物小票或手动添加。AI 识别商品、规格、数量、可见的生产日期，并分为食材、调料和无关内容（推荐商品、日用品、配送费、优惠等）。用户确认、纠错后，食材进入冰箱，按优先级给出存放位置和保质期。
2. **打开冰箱，看什么该先用**：冰箱按冷藏 / 冷冻 / 常温分区，临期和标记先用的食材醒目显示。新鲜度随日期自动变化。用户可滑动标记"用掉""家里没有""先用"。
3. **清冰箱做饭**：点底栏中间的"清冰箱"，默认选中临期和先用的食材，可增减；按"用到所选食材最多、缺料最少"列出有来源的菜谱。常备调料默认视为家里有。
4. **补缺料**：决定做菜后，把缺料加入按品类整理的待买清单，复制或分享给自己 / 联系人。购物平台内的选品与下单由用户完成。

## 页面

| 页面 | 主要内容与动作 |
| --- | --- |
| 冰箱（首页） | 分区物资列表、新鲜度与先用标记、滑动操作、"＋ 入库"入口；空冰箱时突出入库 |
| 菜谱 | 浏览和搜索全部菜谱，按冰箱食材匹配度排序；详情展示来源、原用料和步骤、有 / 缺标记 |
| 清冰箱 | 底栏中间最醒目的按钮；选择要用掉的食材后出菜谱 |
| 待买 | 做菜缺料和用完的常备品，按品类分组，可删除、复制、分享 |
| 我的 | 常备调料 / 常用食材规则、保质期与存放规则、演示模式、数据删除、菜谱来源与许可 |

入库确认是轻量弹出流程。识别失败、重复导入、空冰箱、无匹配菜谱、超出估计期限等状态都需有可继续的操作。视觉略带拟物，有生活感和活力；不用 emoji 当图标；控件紧凑，空间优先留给物资和菜谱。

**数据归属**：所有数据保存在本机的单人空间，不要求账号。后续加入多人协作时再扩展为家庭共享空间。

## 保质期与临期

- 日期分开记录：购买日期、入库日期、生产日期、包装到期日；**不把导入时间当作生产日期**。截图中的"今天生产"等相对日期以截图当天为准。
- 保质期来源优先级：**识别结果 > 本地记忆 > 参考表 > AI 判断**。
  - 识别结果：截图、小票或包装上可见的到期日、生产日期、标注保质期；
  - 本地记忆：用户确认过的同类食材规则；
  - 参考表：App 内置的常见食材保质天数；
  - AI 判断：前三者都没有时的估计，按食材缓存以保持前后一致。
- 每个食材标出取值来源。用户调整后可选择"以后同类食材都按这个"，确认后成为本地记忆规则。
- 新鲜度分为新鲜 / 临期 / 超出估计期限，每天自动重算；超出时提示"请查看后决定"。

## 数据与接入边界

- **识别**：DeepSeek 多模态 API（`deepseek-flash`，官方标注实验性）。App 直连，不部署后端；试用密钥构建时注入、设额度上限，仅发给认识的试用者，试用后作废。超长截图在本机切片后识别。识别时附固定标准食材词表，保证与菜谱用料一致。识别层可替换，备选阿里云百炼 Qwen-VL。
- **菜谱**：[HowToCook](https://github.com/Anduin2017/HowToCook) 全量文本（Unlicense），离线转换后内置；图片不纳入。[厨房计划 API](https://proj.kitchen/api/recipes) 缺少逐条来源和许可，不作为正式内容。
- **平台订单 API**：[淘宝买家订单 API](https://open.taobao.com/api.htm?docId=45&docType=2) 权限未验证，不是首版前提；其他平台无公开消费者订单接口。
- **附近门店**：[高德地点搜索](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)可作后续增强；无门店库存数据时不显示"有货"。
- **系统能力**：相册选图、[Android 接收系统分享](https://developer.android.com/develop/ui/compose/sharing/receive)、相机拍照有官方实现路径；后台监测其他 App 截图不可行，不列入。

## 原型验收与研究指标

- 一位用户可在 Android 手机和模拟器上完成：入库 → 纠错 → 冰箱中看到新鲜度 → 清冰箱做饭 → 有来源的菜谱 → 缺料进待买 → 标记用掉；断网时演示模式可走通。
- 研究记录：入库完成率与耗时、每张截图修正项数、无关内容误判数、保质期被用户修改的比例、建议是否促成做饭决定、数日后冰箱记录是否仍准确。先收集基线，再由团队确定阈值。
- 原型明确展示空冰箱、识别失败、无匹配、估计期限等状态，不以虚构数据掩盖限制。

## 明确不做

- 家庭成员协作、家庭组、成员权限和操作日志。
- 精确库存消耗统计、月度报表、浪费金额和环保贡献。
- AI 编造或改写菜谱；食品安全结论。
- 自动监控其他 App 截图、跨应用悬浮弹窗、自动读取购物账号或代下单。
- 首版部署后端、账号与云同步、iOS / 桌面版本。
- 价格、门店库存或"一键买齐"承诺。
- 现阶段确定会员、广告、硬件、增长方案。
